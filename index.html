Unidad 1.2 · Tema 1

Servidores web e IIS

Idea clave

Un servidor atiende peticiones de clientes por la red. IIS es el servidor web de Microsoft para Windows y .NET, y además trae FTP, SMTP y NNTP.

El ciclo de una petición

1 · RequestEl navegador pide un archivo por IP o dominio
→
2 · ProcesamientoEl servidor busca el archivo o genera la respuesta
→
3 · Response200 OK o 404 Not Found

Tipos de servidores

TipoQué hace
WebEntrega HTML, CSS y JS
CorreoSMTP = salida · IMAP / POP3 = entrada
Base de datosGuarda, recupera y modifica datos estructurados
ArchivosCompartir documentos en red
DNSTraduce dominios (google.com) a direcciones IP

Estático vs dinámico

Servidor estático

  • Envía los archivos tal como están
  • Rápido
  • Ej.: blog simple, landing page

Servidor dinámico

  • Estático + servidor de aplicaciones + base de datos
  • “Construye” la página antes de enviarla
  • Ej.: perfil de Facebook, tienda en línea

Software de servidor web

Nginx
Alto rendimiento, poca memoria. Muy usado como proxy inverso.
Apache HTTP Server
El veterano. Flexible por su sistema de módulos.
Microsoft IIS
Estándar para Windows y .NET.

IIS (Internet Information Services)

  • Servicios incluidos: FTP, SMTP, NNTP y HTTP/HTTPS.
  • Nació en el Option Pack de Windows NT. En Windows 98 se llamaba PWS (Personal Web Server).
  • Funciona con módulos: ASP, ASP.NET y también PHP o Perl mediante CGI.
  • Al habilitar IIS se habilita ASP.

  • Servicios de IIS: FTP, SMTP, NNTP, HTTP/HTTPS.

ASP clásico

Idea clave

ASP (Active Server Pages, 1996) ejecuta VBScript dentro de IIS y le manda al navegador solo HTML. Es SSR, solo corre en Windows y mezcla todo en un archivo .asp (código espagueti).

Cómo funciona

Navegadorpide index.asp
→
IISve la extensión .asp
→
Motor ASPejecuta lo que está entre <% %>
→
HTML simpleel navegador nunca ve el código ASP

Si se pide un .html, IIS lo devuelve tal cual, sin pasar por el motor ASP.

Monolíticos y n-capas

Idea clave

Un monolito es código programado como un solo bloque y ejecutado como una unidad indivisible. Puede ordenarse en capas (Presentación, BLL, DAL), pero sigue desplegándose como una sola pieza.

Arquitectura de 3 capas

Cliente: navegadorthin client · HTTP/HTTPS
▼
UN SOLO DESPLIEGUE EN IIS1 proceso w3wp.exe
1 · Presentación (UI).aspx, controles, validación
▼
2 · BLL · Business Logic Layercoordina, procesa comandos, cálculos y lógica
▼
3 · DAL · Data Access Layerconsultas SQL, conexión
▼
Servidor de base de datosSQL Server, MySQL, PostgreSQL…

Con Process Explorer (Sysinternals) se ve que la app corre en un solo proceso.

Evolución de los modelos

1970sFuncionales
1980sOrientados a objetos
1990sComponentes
2000sServicios (SOA)
HoyMicroservicios

Mainframes: COBOL, RPG, AS400, IBM. Estilos web: cliente-servidor · monolito 1 capa · monolito n-capas · SOA · microservicios.

Descomposición del software

Objetivo: minimizar dependencias y maximizar cohesión.

Funcional (estructurada)

  • Divide un proceso en etapas bien definidas
  • Funciones en C, procedures en Pascal/Basic
  • No hay clases

Orientada a objetos

  • Divide en clases pequeñas, una regla de negocio cada una
  • Ej. de Booch: MasterFile compone FileOfUpdates, MasterRecord, UpdateToCard

Cliente-servidor

Escritorio · thick client

  • Ejecutable instalado
  • Mucho procesamiento local
  • Comunicación por TCP

Web · thin client

  • El navegador
  • La lógica y los datos están en el servidor
  • Comunicación por HTTP/HTTPS

Las 5 características

1 · Acoplamiento fuerte la definitoria
Un cambio en una parte obliga a cambiar otras.
2 · Base de código única
Un solo repositorio.
3 · Despliegue único
Un artefacto; un cambio pequeño = redesplegar todo.
4 · Tecnología uniforme
Un lenguaje, un framework, una BD.
5 · Escalabilidad vertical
Más CPU y RAM. La horizontal es posible pero compleja por el estado compartido.

Ventajas vs desventajas

Ventajas

  • Simplicidad inicial
  • Fácil de depurar
  • Fácil de implementar, sin orquestación
  • Estado global compartido, sin problemas de consistencia
  • Menor costo inicial
  • Menos complejidad operativa
  • Se optimiza una sola unidad

Desventajas (en inglés en el PDF)

  • Difícil de mantener · Maintenance Burden
  • Escalar todo aunque una parte tenga demanda · Scalability Challenges
  • Un error tumba todo · Single Point of Failure
  • Difícil adoptar tecnologías nuevas · Technology Lock-in
  • Equipos grandes se estorban · Development Bottlenecks

Escalado en IIS

Vertical (scale up)

  • Más recursos a la misma máquina
  • Cada application pool = 1 w3wp.exe por defecto
  • Varios worker processes = web garden

Horizontal (scale out)

  • Varias instancias en varios servidores
  • Detrás de un balanceador de carga
Web Forms: archivos .aspx, programación basada en eventos, controles de servidor y code-behind. Laboratorio: 1 capa con VS 2026 y .NET Framework 2.0; n-capas con 4.8 (canciones de PoliMusic).

★ Probable en examen (hay 10 preguntas oficiales en el quiz)

  • Definición: un solo bloque, ejecutado como unidad indivisible.
  • BLL y DAL: qué significan y qué hace cada una.
  • Acoplamiento fuerte, Single Point of Failure, Technology Lock-in.
  • Escalabilidad natural: vertical.
  • Thin client = navegador.
  • Descomposición funcional = etapas bien definidas.
  • w3wp.exe, application pool, web garden. Web Forms = .aspx.

HTTP, AJAX y jQuery

Idea clave

HTTP es petición-respuesta: el servidor nunca habla primero. AJAX permite pedir datos sin recargar la página, pero sigue sin resolver el tiempo real. Por eso existen el polling y los WebSockets.

El problema: el “push” es imposible en HTTP

POST →
Servidorsolo reacciona
✕
Usuario Bno se entera sin recargar

Lo necesitan chats, juegos en línea, apps colaborativas y seguimiento en tiempo real.

De la recarga a AJAX

demo1.asp · tradicional

  • POST a la misma página
  • El servidor espera 10 s (busy wait con Timer)
  • Toda la página espera y se recarga

demo2.asp · AJAX

  • fetch en segundo plano
  • Solo cambia un <p>
  • La página no se recarga
  • Timer = segundos desde medianoche. 86400 = segundos de un día, corrige el cruce de medianoche.
  • El servidor sabe que es AJAX por la cabecera X-Requested-With: XMLHttpRequest.
  • En ASP se lee como Request.ServerVariables("HTTP_X_REQUESTED_WITH").
  • Responde texto plano y corta con Response.End.

  • C# usa corchetes: Request.QueryString["action"]. VBScript usa paréntesis.
  • Formato "yyyy-MM-dd HH:mm:ss": MM = mes, mm = minutos.
  • Dos variantes: <script runat="server"> en el .aspx, o code-behind (clase partial que hereda de System.Web.UI.Page).

★ Probable en examen

  • HTTP no sirve para tiempo real: el servidor no puede iniciar la comunicación.
  • AJAX = Asynchronous JavaScript And XML; actualiza sin recargar.
  • Cabecera X-Requested-With: XMLHttpRequest.

Desventajas

  • Carga con muchos clientes simultáneos
  • Reabrir petición tras cada respuesta
  • Menos eficiente que WebSocket

1 · Una conexión por petición
Cada una implica un handshake TCP.
2 · Cabeceras verbosas

3 · Consultas vacías
Sobre todo en short polling.
4 · Un solo sentido
El cliente siempre inicia.

Solución: una conexión persistente y bidireccional → WebSocket.

2 · Las demás preguntas

Profe¿Qué es RHEL?

Red Hat Enterprise Linux: la distribución Linux empresarial de Red Hat. Está construida sobre software open source, pero se vende con suscripción de soporte comercial. Viene al caso porque SQL Server corre en Linux (desde la versión 2017), y RHEL es una de las distribuciones soportadas; por eso también puede correr en un contenedor Docker.

Profe¿Qué es bcp en SQL Server?

bcp = Bulk Copy Program: utilidad de línea de comandos para importar o exportar grandes volúmenes de datos entre una tabla de SQL Server y un archivo (CSV, texto). Modos: in (archivo → tabla), out (tabla → archivo), queryout (resultado de una consulta → archivo).

Profe¿Qué es ADO.NET?

El conjunto de clases de .NET para acceder a bases de datos (espacios System.Data y System.Data.SqlClient). Es el sucesor de ADO, que usaba ASP clásico. Es lo que usan los Labs 1, 3 y 4.

Profe¿Qué es el CLR?

Common Language Runtime: el entorno de ejecución (máquina virtual) de .NET. El compilador de C# genera CIL/MSIL (lenguaje intermedio); el CLR lo compila a código nativo con el JIT (Just-In-Time) y además se encarga del recolector de basura (garbage collector), la seguridad de tipos y las excepciones. El código que corre sobre el CLR es código administrado (managed); el de C/C++ nativo es no administrado (Tema 5).

Profe¿Qué es Entity Framework?

El ORM (Object-Relational Mapper) de Microsoft para .NET: mapea tablas a clases y filas a objetos, y permite consultar con LINQ en lugar de escribir SQL. Piezas: DbContext (la conexión/sesión) y DbSet<T> (una tabla). Enfoques: Code First (las clases generan la BD, con migraciones) y Database First (la BD genera las clases). EF Core es la versión multiplataforma para .NET moderno.

Profe¿Qué es ad hoc? (tu apunte: “cuando no se opta por un ORM”)

Una consulta ad hoc es SQL escrito “para este caso” directamente en el código, en lugar de usar un ORM (como Entity Framework) o procedimientos almacenados. Es exactamente lo que hacen las clases DAL de los Labs 3 y 4: cmd.CommandText = "SELECT ... WHERE [USERNAME] = @USERNAME". Ventaja: control total y rendimiento. Riesgo: inyección SQL si se concatena texto del usuario, por eso se usan parámetros.

Profe¿Qué es WebSocket?

Un protocolo de comunicación bidireccional (full-duplex) y en tiempo real sobre una sola conexión TCP persistente. Empieza como petición HTTP con Upgrade: websocket; el servidor responde 101 Switching Protocols y desde ahí cliente y servidor envían mensajes cuando quieran, sin volver a pedir. Esquemas ws:// y wss:// (cifrado con TLS). Resuelve lo que el polling solo simulaba. En Node se usa la librería ws (Lab 5) o Socket.IO (Lab 7). El estándar es el RFC 6455 (dato complementario, no está en los PDFs).

3 · Preguntas hermanas probables

Docker¿Imagen vs contenedor?

La imagen es la plantilla (solo lectura) que se descarga; el contenedor es una instancia en ejecución de esa imagen.

SQL¿Por qué 14333 y no 1433?

Para no chocar con un SQL Server instalado en la PC, que ya usa el 1433. El contenedor sigue usando 1433 por dentro.

SQL¿Cómo verificas que el puerto escucha?

telnet localhost 1433 o en PowerShell Test-NetConnection localhost -Port 1433.

SQL¿Para qué sirve SQL Profiler?

Para ver en vivo las sentencias que la app envía a la BD. En el lab se activan los eventos RPC:Completed y SQL:BatchStarting.

SQL¿Qué es SSMS?

SQL Server Management Studio: el administrador gráfico de SQL Server.

SQL¿Qué es un ORM?

Object-Relational Mapper: traduce entre objetos del código y tablas relacionales. Ej.: Entity Framework (.NET), Hibernate (Java). Lo contrario es SQL ad hoc con ADO.NET.

SQL¿Qué es la inyección SQL y cómo se evita?

Meter código SQL en un campo de texto para alterar la consulta. Se evita con consultas parametrizadas (@USERNAME en ADO.NET, ? con ADODB.Command en ASP).

.NET¿Qué es LINQ?

Language Integrated Query: consultas escritas en C# (from s in db.Songs where … select s) que EF traduce a SQL.

Seguridad¿SHA1 vs PBKDF2?

En los labs, GeneratePasswordHash usa SHA1 (hash simple, hexadecimal). HashPassword usa PBKDF2 (Rfc2898DeriveBytes) con salt aleatorio de 16 bytes y 100.000 iteraciones: mucho más seguro contra fuerza bruta.

WebSocket¿WebSocket vs Socket.IO?

WebSocket es el protocolo. Socket.IO es una biblioteca (capa de abstracción) encima: eventos con nombre (emit/on), reconexión automática y respaldo a long polling. Un cliente WebSocket puro no puede hablar con un servidor Socket.IO.

Chat en tiempo real con WebSocket

Lo que hiciste

Un chat con Express + ws: el servidor recibe un mensaje JSON y lo reenvía a todos los clientes conectados (broadcasting). Luego una versión v2 estilo WhatsApp hecha con IA.

Comandos

Servidor y cliente

  • Broadcasting (difusión): en ws.on('message') se reenvía a todos los clientes con conexión abierta.

Laboratorio 6

WebSocket seguro con JWT

Lo que hiciste

Generaste un certificado con OpenSSL, levantaste un servidor HTTPS + WSS en el puerto 5000 con rutas /auth y /ws, y el chat solo acepta clientes con un JWT válido.

Flujo completo

1 · Loginfetch /auth?username=…&password=…
→
2 · jwt.sign{ sub, username }, expira en 900 s
→
3 · WSSwss://localhost:5000/ws?token=…
→
4 · jwt.verifyválido: entra · inválido: ws.close()

Certificado con OpenSSL (Windows)

  • OPENSSL_CONF apunta al archivo de configuración openssl.cnf de la versión portable.
  • rsa:4096 = clave RSA de 4096 bits; -days 365; -nodes = sin contraseña.
  • Datos: EC, Pichincha, Quito, EPN, FIS, Common Name = localhost.
  • Resultado: cert.pem y key.pem, copiados a backend/.

Estructura y paquetes

Carpetas
LabWebAv-WebSocketChatSeguroJWT/frontend (index.html, script.js, style.css)
…/backend (index.js, cert.pem, key.pem)
Paquetes
npm install express ws jsonwebtoken
Ejecutar: node --watch index.js

Servidor

  • El WSS se monta en la ruta /ws: new WebSocket.Server({ server, path: '/ws' }).
  • El token se saca de la URL con url.parse(req.url, true).query.token.
  • En cada mensaje se vuelve a verificar el token de cada cliente: si expiró, recibe “Error: Your token is no longer valid” y se cierra.
  • expiresIn: 900 = 15 minutos (buena práctica de expiración corta).
  • /userInfo devuelve datos del usuario solo con un token válido (decodedToken.sub).

Pruebas y depuración

  • Se abre https://localhost:5000 en el navegador (no con Live Server). Aparece “la conexión no es privada” porque el certificado es autofirmado, no lo emitió una CA → “Avanzado” → “Continuar a localhost”.
  • DevTools → Network → WS: en las cabeceras se confirma wss.
  • Depurar el cliente: F12 → Sources → breakpoint en script.js. F10 = siguiente línea, F8 = continuar.
  • Depurar el servidor: VS Code → Run and Debug → Node.js, con breakpoint en index.js.
Laboratorio 7

Chat con Socket.IO

Lo que hiciste

El mismo chat, pero con Socket.IO: una biblioteca que es una capa de abstracción sobre WebSockets y trabaja con eventos con nombre.

Lo importante

io.emit('mensaje', …)
Envía el evento a todos los clientes conectados, incluido el que lo originó: broadcasting.
socket.emit / socket.on
El cliente emite el evento “mensaje” y escucha el mismo nombre de evento.
/socket.io/socket.io.js
No está en public/: el propio servidor Socket.IO entrega la biblioteca cliente, que define io().
textContent vs innerHTML
Con textContent, un <script> se muestra como texto y no se ejecuta: evita XSS (Cross-Site Scripting).
Servidor
http.createServer(app) + new Server(server) (de require('socket.io')).
Postman
New → Socket.IO → http://localhost:3000 → Connect → Events: escuchar “mensaje” → enviar JSON {"username":"Postman","text":"Postman aquí"}.
